Section 1

How onboarding fits together

Everything in RentRewards hangs off one chain. Each link has to exist before the next can be added, and each person is brought in by someone who already has access.

Who onboards whom

Who is onboardedWho does itWhere in the appHow they get access
Property managerCompany adminAdministration → UsersInvitation link; sets own password
Landlord (record)Company admin or property managerPortfolio → Landlords → Add landlord—
Landlord (portal login)Company admin or property managerLandlord page → Landlord portalInvitation link; sets own password
PropertyCompany admin or property managerPortfolio → Properties → Add property—
UnitsCompany admin or property managerProperty page → Units tab—
Manager ↔ propertyCompany adminProperty page → Overview → Property managerAssigned manager sees the property at once
Tenant (record + lease)Company admin or property managerTenancy → Tenants → Add tenant—

Recommended order: property managers → landlords → properties → units → tenants & leases → move-in → portal invitations. Each step needs the one before it: a property needs its landlord, a lease needs a vacant unit, and a tenant needs a lease before the portal has anything to show them.

Before you start

Everyone signs in on the same page. What they see afterwards depends on their role.

Roles that take part in onboarding

RoleCan onboardSees

Property managerLandlords, properties, units, tenants, leases, move-ins, landlord and tenant invitationsOnly properties assigned to them (and anything on them)

TenantThemselves, by self-registration (if allowed)Their own tenancy in the tenant portal

Section 7

Invitations: the rules

Property managers, landlords and tenants all join through the same kind of invitation.

  • One-time link. Each invitation is a unique link. It works once; after the person sets their password it stops working.
  • 72 hours. A link expires 72 hours after it is sent. Send a new one if it runs out.
  • Newest wins. Sending a new invitation to the same person cancels any earlier link.
  • Revoke. A pending invitation can be revoked from where it was sent, without sending another.
  • One login per email. An email address can belong to only one RentRewards login. Each landlord and each tenant can have one portal login.
  • Email delivery. Invitations are emailed. Until email delivery is connected, the person sending it also sees the link once so they can share it themselves.
  • Passwords. At least 8 characters, including a letter and a number. RentRewards stores only a secure hash of the link and of the password.

Section 8

Quick reference

Onboarding a property manager

  • Users → Invite a property manager (name, email)
  • Share the link; they set a password
  • Assign them on each property’s Overview

Onboarding a landlord

  • Landlords → Add landlord (type, name, phone, payout)
  • Add email and KRA PIN
  • Landlord page → Landlord portal → Send invitation

Onboarding a property

  • Add property (landlord, name, type, county, town)
  • Units tab: one by one, a run, or a spreadsheet
  • Assign the property manager
  • Optional: list vacant units

Onboarding a tenant

  • Tenants → Add tenant (name, phone, email)
  • Sign the lease on a vacant unit
  • Move-ins → Complete
  • Tenant → Portal tab → Send invitation

Common problems

ProblemFix
“That email address already has a RentRewards login.”Use a different email, or ask the person to sign in with the existing one.
Invitation link “no longer valid”It expired, was used, or was replaced. Send a new invitation.
A property manager cannot see a propertyAssign them on the property’s Overview tab.
Can’t invite a landlord or tenantAdd an email address to their record first.
No unit offered when signing a leaseOnly vacant units are offered. Add units, or end the current lease.
A unit upload added nothingFix the rows listed in the message and upload the whole file again.

Unit spreadsheet format

Used by Upload a spreadsheet on a property’s Units tab. Download the template there for a ready-made file.

Column headingWhat goes in itExample
unit_numberRequiredDoor number. Unique within the property.A1
monthly_rentRequiredRent in KES. Commas and “KES” are ignored.25000
typeOptionalUnit type code or name. Blank means One Bedroom.ONE_BEDROOM
floorOptionalWhole number. Ground floor is 0.0
bedroomsOptionalWhole number. Blank means 1.1
bathroomsOptionalWhole number. Blank means 1.1
depositOptionalDeposit in KES. Blank means 0.25000
service_chargeOptionalMonthly service charge in KES. Blank means 0.2000

Unit types

BEDSITTER, STUDIO, ONE_BEDROOM, TWO_BEDROOM, THREE_BEDROOM, FOUR_BEDROOM, MAISONETTE, SHOP, OFFICE_SPACE, HOSTEL_ROOM, OTHER (the names, e.g. “One Bedroom”, also work).

Rules

  • The first row must be the column headings. Order does not matter; extra columns are ignored. Common headings such as “Unit No” or “Rent” are recognised.
  • Each unit number may appear once and must not already exist on the property.
  • Up to 500 units per file. Every unit is added as Vacant.
  • Excel files are not read directly: save as CSV first.
  • If any row has a problem, nothing is added and the message lists every row to fix.
